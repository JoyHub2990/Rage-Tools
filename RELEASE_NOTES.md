# RAGE Tools

## Added
- **Terrain painter**: import several props at once. Each gets its own row — hide it while you paint what's behind, save it on its own, or save them all into one folder.
- **Light presets**: a saved library of light settings, applied in one click. Never moves the light or changes where it points.
- **Multi-select**: Ctrl+click in the world to select several things — MLO instances, props, anything — and the gizmo moves them together.
- **Particles**: import your own image as a sprite sheet (`.dds`, `.png`, `.jpg`, `.bmp`). It's embedded into the `.ypt`, so the effect carries its own texture.
- **Animations**: open a `.ytd` to texture the model you're animating.
- **Animations**: opening a `.ycd` now loads its UV and bone tracks into the editor and plays them.
- **Navmesh**: `Del` now disables polygons instead of deleting them, keeping every index intact. Outright deletion is still available under Editing.
- **MLO**: choose which names are drawn in the viewport — selected only, everything, or off.
- **RPF viewer**: **texture dictionaries** like OpenIV - a card in the bottom-left of the picture says which texture names the model could NOT find (the reason it is grey), lists the dictionaries attached, and attaches more: a `.ytd` from disk, or one pulled straight out of the game archives by name (vehshare, mapdetail...).
- **RPF viewer**: **weapon assembly** - open a gun and a Weapon tab finds its components in the archives, says which slot each snaps to (its own AAP bone), and attaches them to the weapon's WAP bones in a click. Variants are told apart from components and open as their own model.
- **RPF viewer**: **Load YTD** browses the archives as well as the disk, and opens in the model's own folder every time - the dictionary is nearly always beside the model. Browse disk... is one click away, and it opens on the model's folder too.
- **RPF viewer**: **weapon components come from the game's metas** - weapons.meta says which components go on a weapon and on which bone, weaponcomponents.meta turns each into a model, weaponarchetypes.meta names its texture dictionary. So the shared attachments (scopes, muzzles, grips) are found wherever they live, not just beside the weapon. The Mk2 carbine went from 6 components to 33.
- **Project window**: **Ctrl and Shift click** props like CodeWalker - the tree's selection is the world's, so the gizmo moves them together.
- **Materials**: **the texture's own properties**, so you don't go back to Blender or zmodeler for them - what the texture IS (usage: DIFFUSE, NORMAL, SPECULAR, TINTPALETTE...) and how the game may stream it (the usage flags, and the extra flags beside them). A normal map stamped DIFFUSE was a re-export; now it's a dropdown, with one click to set what the slot it sits in is for.
- **Materials**: **copy a material onto another** - the shader, the pass, every parameter and every texture, onto one material or every one you have selected. A prop with one material right and eleven that should match it is now one copy and one paste.
- **Materials**: **every sampler the format declares** can be added, not the eight with hand-written labels - the terrain layer samplers, the fur height samplers and 263 more. And a texture slot can now be **removed**, not only emptied.
- **Particles**: **sprite sheets and their animation, the way Blender shows them** - the sheet drawn large with its grid ruled over it, every cell numbered, the cells a particle can start on outlined, the one playing right now highlighted, and a preview thumbnail flipping through the run beside the controls. Click a cell to make it the start cell. **Animate** turns a still sheet into a flipbook, and the frames, fps, loop mode (once / loop / cycle inside the start cells like the game's insects), over-lifetime, frame blending and hold-last are all written into the real fields of the `.ypt`, so the game plays what the preview plays.
- **UI**: **dockable panels**. Appearance > Layout switches between Classic (the fixed side columns, still the default) and Dockable - every panel gets a title bar you can drag to any edge, tab together with another, or close. Your arrangement is remembered; "Put the panels back where they started" undoes it. The switch is live, no restart.
- **MLO Creator**: **Export for the game...** - one button that writes the `.ytyp`, the `.ymap` that places it AND the `_manifest.ymf` into one folder, then lists what you still have to put beside them. The manifest is the file that tells the game the `.ymap` needs the `.ytyp`; without it an otherwise-perfect interior loads nothing and says nothing. **Save .ytyp** and **Save .ymap** are now buttons on the toolbar too, instead of being buried in a popup.
- **MLO Creator**: **Add room** (blue), **Add portal** (amber) and **Snap all corners** (green) each carry their own colour, so the three things you reach for most are findable at a glance. The toolbar says which tool is live and what the keys are (Q select, W move, E rotate, T scale) instead of spending four buttons on it.
- **MLO Creator**: the **shell goes into limbo as an entity** by default, alongside the props. If the archetype also names its own drawable the shell would be drawn twice - that is said plainly under the checkbox, with a **Make it assetless** button that fixes it in one click.
- **MLO Creator**: **Import .ybn (collision)...** right under the shell picker. The archetype does not hold its collision, it *names* it - so this proves the file really is a collision file (and shows its bounds), names it in the `.ytyp`, and copies it beside the `.ytyp` when you export. It also warns when the `.ytyp` names collision that cannot be found.
- **MLO Creator**: **Shift+drag copies** the selected prop, like the Lights editor - the copy moves and the original stays put.
- **Lights**: a **del** button beside Save As on every prop row. It was in the right-click menu as "Close", which is not the word you look for when you want the prop gone.
- **MLO Creator**: **Add room**, **Add portal** and **Add entity** are buttons on the toolbar. Add entity is CodeWalker's flow - type an archetype name, or leave the box empty for a placeholder you rename later. It lands in the room you have selected (limbo if none) and its model is looked up on the spot. Sel / Move / Rot / Scale and Assets came off the toolbar (Q / W / E / T already switch tool; Assets is a page).
- **RPF explorer**: **Export XML...** writes a converted file to disk instead of only showing it, and **View hex** shows the raw bytes with offsets and characters - what to reach for when a file has no XML converter, or has one and comes out wrong.
- **`ped_fur` is rendered**, not just listed. The animals' coat (cats, dogs, coyotes) is shell fur like `grass_fur` but shares **not one parameter** with it, so it fell through the grass path and drew flat. It now draws its shells with the game's own numbers, read off `a_c_cat_01` in your install: `furLength`, a `furMinLayers`..`furMaxLayers` range picked by distance, the `NoiseSampler` strand mask tiled by `furNoiseUVScale`, `furAttenCoef` tapering root to tip, and `furSelfShadowMin` darkening the skin under the pile. All twenty-three of its parameters are named and editable in the material editor.
- **`.ydd` files open in the Light and Material editors.** Every drawable in the dictionary becomes its own prop - separately hideable, selectable and material-editable - which is what lets you work on a ped at all. They're read-only (there's no `.ydd` writer); Save As still writes a `.ydr`.
- **MLO Creator**: **Ctrl+C / Ctrl+V** props between rooms - copy any number, select the room you want, paste. They keep their position (rooms overlap in space, so "the same place, in that room" is what's meant) and the originals stay put.
- **MLO Creator**: **Add entity** places a prop in one click now, with no dialog - rename it on the Entity page afterwards.
- **Import from GTA V**: **Import map (.ytyp + .ymap)...** takes any mix of both at once. The archetypes are loaded first and the placements after - the order that works, since a `.ymap` loaded before its `.ytyp` finds no archetype for anything it names and places nothing.
- **Lights**: **Move lights to...** - select any number of lights and give them to another prop. Every setting is kept; only the `.ydr` they are saved into changes. They stay exactly where they are in the world by default, or keep their offset on the prop if you'd rather.
- **RPF viewer**: **ped texture variants** - a `.ydd` whose textures come in lettered sets (`_a_`, `_b_`, `_c_`...) shows every letter found beside it; click one to see it.
- **RPF explorer**: the search is scoped to the **selected branch** of the tree by default - everything under the node you are on, however deep. Whole install and This folder only are one click away.
- **World**: load your **mods folder** (the OpenIV layout - GTA V\mods\) so the world streams your modded archives instead of the stock ones, and pick the **DLC level** the map is built at. Changing either reloads the world; unsaved edits block the switch instead of being thrown away.
- **World**: the **heightmap** is drawn at last - as a shaded relief surface (slope-lit, coloured by height), not a flat tint. Mount Chiliad looks like a mountain now. Options > Helpers > Heightmap.
- **Fur grass**: the `grass_fur` shaders are rendered as the game renders them - eight shells pushed out along the normals, each keeping fewer strands of the comb texture, self-shadowed from root to tip. On 879 models in the install (downtown lawns, verges, banks) that were all drawn flat before. Only within 25 m, as the materials themselves ask.
- **World**: a `*` marks a prop with unsaved changes, and "Show me where" flies to the selected prop and opens its `.ymap` in the project tree.
- **World**: **New project**, **Open project** and closing the **Project window** put the world back the way the archives have it - moved and deleted props are back. The window's x asks Save / Don't save / Cancel and closes the project instead of hiding it.
- **UI**: one Appearance menu in the top-left for theme, accent and interface size — with scaling for 1440p, 4K, 5K and 8K.

## Fixed
- **Navmesh**: every edit was cutting ~13% of the cell's pathfinding links, which is what broke traffic around edited areas. Deleting a polygon also shifted the indices that neighbouring `.ynv` files point at, and picking a type for a newly drawn polygon didn't change its colour.
- **Navmesh generator**: it made one polygon per grid cell, so a small area could use up the format's whole 16,383 limit. Flat runs are merged now — a flat 8×8 patch went from 64 polygons to 1.
- **Animations**: bone animation never played, `.ycd` files couldn't be read from the game archives at all, the timeline ignored the opened clip's length so animations wrapped early, and there was an ImGui "conflicting ID" warning in the panel.
- **UI**: panel padding lost its DPI scaling when switching workspace, panel labels were clipped on high-DPI screens, and the selected object was hard to pick out — it now has a dark outline and corner brackets.
- **Materials editor**: "reset" on a parameter went to the shader preset's default (specular fresnel 0.96) instead of the value in the file (0.75); it goes back to the file's value now, and to the preset default only for a parameter the file never had. The Save / Save As / Project buttons were cut off at the panel edge on high-DPI screens; the rows wrap now.
- **RPF viewer**: the Textures tab called a texture "not found" that an attached dictionary was plainly providing.
- **MLO Creator**: the shell was written into the `.ytyp` **twice** - once as the MLO archetype and again as a prop archetype, once it became a limbo entity. Nothing may claim the interior's own name now.
- **MLO Creator**: the vertex snap searched only the mesh the ray happened to hit, so a vertex right under the cursor belonging to a different object was never a candidate and a vertex of the wall behind it won instead. Every mesh near the cursor is considered now.
- **MLO Creator**: the manifest is written as `_manifest.ymf`, not `_manifest.ymf.xml`. **Add room** is amber like Add portal (the blue read as the theme's own button colour). The three "from vertices" pickers are off the right panel.
- **Particles**: the sprite-sheet **Frames** and **fps** boxes clipped anything past one digit - 30 showed as "3". They are measured from the widest value they can hold.
- **Particles**: worked out how the game actually slices a sprite sheet - **the grid is derived from the frame count** (the factor pair whose cells come out most square: 49 frames is 7x7 even on a 1:2 sheet, 32 on a 2:1 sheet is 8x4; verified against every flipbook texture in the install, drawn out and read by eye). The `.ypt` has no grid field anywhere, which is why a custom sheet that "looked right in the tool" played as the whole sheet per particle in game. The preview now slices exactly the way the game will, and the panel states the in-game grid for your frame count - **author your sheet to that layout and it animates in game**. Everything else on the page (frame count, rate, loop mode, blending, hold-last, start cells) exports, verified by save-and-reload with an imported texture.
- **RPF explorer**: searching a folder that is **not** the GTA install (a FiveM resources directory) returned nothing unless you used "This folder only". The search index is built from the install and keyed by install-relative path, so an added folder has no entries in it at all - "Whole install" and "Selected branch" were both walking an index that could not see it. Those folders are now searched on disk instead, including inside any `.rpf` under them, and a whole-install search covers them too.
- **MLO Creator**: the shell becomes its limbo entity **the moment you open it**, not when you export - so the tree shows what will actually be written.
- **MLO Creator**: **Add entity** with an empty box now places a real base-game prop, so you can see it and replace the name, instead of an invisible made-up one.
- **Particles**: the sprite-sheet cell numbers were unreadable - too small, and white-on-flame. They scale with the cell now and sit on a dark chip so they read over any sheet.
- **"2 visible items with conflicting ID"** errors in the MLO Creator and the props list - two buttons really did share an id (two `More...`, and prop rows keyed on a path that can repeat or be blank). Every row and toolbar id is unique now.
- **Buttons cut off at the end of a row** - the props list reserved a fixed 118 pixels for `(93) hide Save As`, so at any interface scale above 1.0 "Save As" was clipped to "Sa". The width is measured from the actual text now, so it fits at every scale; the archive size columns had the same bug.
- **Lights**: hiding a prop now hides its light **markers** too. The lights already stopped lighting, but their markers kept being drawn - hiding a prop left a field of floating diamonds over nothing.
- **Go to selected (G)** flew to the selected *light* whatever you had picked since, so clicking a prop and pressing G took you to a light on something else. A light still wins when it is on the prop you have active; a prop picked afterwards wins over a light belonging to something else. The tap window went from 0.25 s to 0.35 s.
- **MLO Creator**: the `.ytyp` named **no collision** unless the model had an *embedded* bound - so the normal workflow (a `.ybn` beside the model) exported an interior you fall straight through, and OpenIV/CodeWalker showed no `.ybn` link. It is now filled in from a `.ybn` sitting beside the model, whether the shell was auto-detected or picked by hand, and an interior that has collision but names none is reported instead of exported in silence.
- **World collision**: a project's collision only drew if you had already opened the collision view *before* importing the map - the only order anyone uses (import first, check collision second) showed nothing of yours, and an edited copy of a game .ybn never took the game's place. The collision view now learns the project's files the moment it is created, whichever came first. Also: a **mods/DLC switch** now resets the collision picture too (a .ybn deleted from the mods folder was still indexed, cached and drawn from the old archives), and **Remove from Project** on a .ybn row now removes the loaded file, not just its name. And **clicking** your collision selects *your* file: the pick ray-tested the game's copy of a same-named .ybn (so the picture was yours but the selection was the old one) and never tested a custom .ybn at all.
- **Photo mode** is only offered in **Lights** and **Cinematic** now. Everywhere else the panels *are* the work, so the button just blanked the screen and left you hunting for the key back. `P` no longer does it outside those two, and switching away from them leaves photo mode behind.
- **Materials workspace**: opening straight into it showed "Open a .ydr or .yft to edit its materials" with the file already open - the panel was still listing the Lights workspace's scene, because the binding only ran on a workspace *switch* and never for the one the window opens on.
- **World**: a project's **.ybn collision files** were carried by name only and never drawn - edited and custom collision did not show when you switched to collision. They are loaded now and take the game's place by name.
- **Weapons**: a component whose weapon uses **custom bone names** landed at 0,0,0; the bone now comes from the weapon's own attach point, with a loose match behind it.
- **Materials editor**: vehicle materials were missing the environment reflection and the licence-plate slots and letter block; the vehicle presets carry them now, named rather than raw.
- **RPF explorer**: the pop-out handles sat on the file list's scrollbar and first column; the list keeps clear of them now.
- **RPF viewer**: a model opened before the archive index finished kept its shared textures (the weapons' detail map, for one) empty and reported as missing until it was reopened; the found list of a weapon's components belonged to the last weapon opened; components appeared twice once attached, with the detach elsewhere; finding components only looked in the archives, never beside a loose file.
- **World reset**: "New project" did not put deleted or moved props back - the edit lived in the Project window's copy of the file, which is the same object the world draws. Fixed properly, and a delete now brings its ymap into the project like every other edit.
- **Water**: was a flat opaque colour with a hard edge at every bank. It is the game's water again - clear in the shallows with the bottom showing through, foggy with depth, ripples, the sky's reflection at grazing angles, the sun's glint - without the white sheets that made the flat colour necessary before.
- **Weapons**: every gun using a `_palette` shader (most of them) was invisible in the model viewer - only the sights and markings drew. The diffuse alpha on those shaders is a palette lookup, not transparency, and the viewer was throwing the body away as transparent.
- **Camera**: every section now remembers its own view. Eight of the ten were never tested and the World was the worst of them — its start-up spawn overrode the camera you left, so it snapped back to the same spot every time. Cinematic and World still share one view on purpose.
- **World**: "Discard edits" only cleared the save list and told you to reload; it puts the files back now.
- **NavMesh**: removed the Photo mode button, which only ever hid the thing you were looking at.

## Notes
- Skinned props don't animate in the preview yet. Rigid bone-driven models (fans, doors, levers) do.
